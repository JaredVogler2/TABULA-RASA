# 09-INSTITUTION-DSL — Endogenous institutions and executable rule grammar

Read CLAUDE.md and prompts/00-MASTER.md. Implement this phase; record evidence, update progress, commit.

Design a generic declarative institution substrate, not preprogrammed civilization milestones. Agents propose names and text plus bounded typed rules via generic predicates, conditions, permissions, commitments, membership, resource transfers, obligations, expiry and dispute/withdrawal mechanisms. Explicitly separate semantic narrative from executable effect. Example affordances: if consenting agents A and B each escrow resources, exchange atomically; if a group approves a proposal by its previously adopted decision rule, activate bounded rules for consenting scope. Do not bootstrap majority government or currency by default. Use resource conservation, bounded transfer/authority, non-recursive rule evaluation, fuel limits, acyclic dependency checks and canonical AST serialization. Reject unsafe/inexpressible proposals with explainable diagnostics; do not silently invent mechanics to satisfy rhetoric. No arbitrary JavaScript, SQL, shell, filesystem or HTTP. Rules cannot override world invariants, impersonate others or access private memory. Define institution lifecycle proposed → reviewed → ratified/active → amended/dissolved; consent/default conventions are designer affordances, prominently disclose. Allow competing institutions and overlaps; deterministic precedence and dispute outcomes; model coercion only via explicit bounded in-world mechanics, never real user targeting. 
Gate: generic rules can represent voluntary exchange, mutual aid and collectively funded infrastructure without named prebuilt institutions; independent validator and fuzz tests reject resource creation, privilege escalation and infinite loops. Demonstrate from a scripted test proposal only as capability, not evidence of spontaneous emergence.
