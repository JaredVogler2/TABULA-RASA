# Specialist — release acceptance matrix

For each criterion record exact command, expected, actual, evidence path, status (PASS/PARTIAL/BLOCKED/NOT RUN), commit and caveats.
1. Fresh install, lint, typecheck, unit, build, E2E.
2. Headless seeded 50-agent world; resource/authority invariants; hash replay; invalid intent tests.
3. Offline baseline playable with zero credentials; live state rendered, all core interactions real.
4. Private observations, memory provenance, independent agents and no hidden scripted institution progression.
5. Institution DSL validated and executable; fuzz rejects escape, overflow, infinite evaluation, forged consent.
6. Branching identical history and no-cost replay; corrupt import safely rejected.
7. Authenticated live endpoint only; keys excluded from browser/logs; all request paths share ledger; race/timeout/retry tests; public cannot spend.
8. Mock/replay integration verified; live smoke separately approved or BLOCKED, never substitute mock for live.
9. Experiment lab paired seeds, operational definitions, honest uncertainty and reproducible exports.
10. Visual screenshot rubric and actual mobile/desktop browser flows; hardware/human tests distinguished.
11. Performance measured with device, scenario, FPS and memory, graceful fallback.
12. Vercel preview/release verified if authorized; deployment status and rollback honest; all extra costs disclosed.
13. Independent adversarial review, evidence-backed Fable scorecard, known issues, license manifest and owner setup guide.
No release with critical budget/security/data-integrity defects. Offline-only public release is acceptable if live enablement remains blocked. Never conflate implemented with tested, or tested with deployed.
