# 16-ADVERSARIAL-QA — Independent correctness, security and model behavior QA

Read CLAUDE.md and prompts/00-MASTER.md. Implement this phase; record evidence, update progress, commit.

Act as skeptical reviewer independent of implementation. Define acceptance tests before running, do not alter assertions simply to pass. Validate resource/accounting, authority, consent, institution rule engine, reproducibility, hidden-information isolation, no cross-session data leakage, prompt injection resistance, malicious proposals, stale state, race conditions, budget bypass, auth/CSRF, denial-of-service, dependency and secret scanning. Use fuzz/property/metamorphic tests, mutation tests for core invariants, golden replay fixtures, chaos tests on provider and DB, mock API responses with malformed/partial data, disconnects, timeouts and usage omissions. Inspect generated client bundle for secrets, source map and env exposure. Test real browser E2E and mobile emulation with screenshots; manually audit visual details and keyboard access. Review cases where artificial citizens use political/cultural language; ensure it is contextual fiction, no model agency outside world, no real-world person targeting. Audit code provenance, licenses, third-party services and telemetry. Review false-emergence claims and selection bias. 
Gate: independent report with severity, reproduction, actual results, fixes and remaining risks; no critical security/budget/data integrity issues before live enablement; human playtest and physical-device test explicitly marked not run if unavailable.
