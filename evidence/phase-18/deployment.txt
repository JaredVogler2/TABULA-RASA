Two things docs/DEPLOYMENT.md listed as unknown until a first build:

  1. Which pnpm the builder picks: 10.28.0, the version `packageManager` names. Settled.
  2. Which Node.js runs it: NOT OBSERVED. The project's own setting reads 26.x, the platform's default for a
     new project. `package.json` says `"engines": {"node": "22.x"}`, which Vercel's documentation says
     overrides the project setting (docs/research/vercel-platform.md §2). The build log does not print the
     version it used, and nothing the site serves tells. Setting the project's Node.js Version to 22.x in its
     settings would make both say the same thing.

What could not be read: the project's environment variables (the assistant's connector is refused the list,
403). What the site itself shows is in release-check-deployed.txt and deployed-by-hand.txt: it behaves as a
deployment with no owner configured.

One header the platform adds: `access-control-allow-origin: *` on what it serves from its cache as static
content — the pages and /api/health. The functions (every other /api route) do not carry it; a request to one
from another origin is given no such header, and one that would change anything is refused with 403.
