# Vercel + Next.js 16 platform facts

**Verified on 2026-11-25 from official documentation** — vercel.com and nextjs.org only, read as Markdown through each page's `.md` URL (as HTML for the Marketplace listing and the fair-use lists, which have no complete Markdown form). Next.js docs were at `@doc-version: 16.4.6` (https://nextjs.org/docs/llms.txt). Text in "double quotes" is verbatim from the cited page. Nothing here was tested against a live deployment or account. Facts that no official page confirmed are tagged **UNCONFIRMED** and collected in the last section. Some Vercel pages carry a placeholder stamp (`last_updated: 2018-10-20`), so page dates are not reliable evidence of freshness.

## 1. Vercel Functions: duration, memory, body size

- Fluid compute is on by default: "As of April 23, 2025, fluid compute is enabled by default for new projects." It can be toggled per project (Functions settings) or with `"fluid": true` in `vercel.json`. (https://vercel.com/docs/fluid-compute)
- Max duration with Fluid (Node.js, Bun, Python) — Hobby: default "300s (5 minutes)", maximum "300s (5 minutes)", extended "-". Pro and Enterprise: default "300s (5 minutes)", maximum "800s", extended maximum "1800s (30 minutes) Beta". (https://vercel.com/docs/functions/limitations#max-duration)
- "Values above 800 seconds require function-level configuration and are only supported for specific Node.js, Bun, and Python runtime versions" (`nodejs22.x`, `nodejs24.x`, `nodejs26.x`). On overrun "a 504 error code (`FUNCTION_INVOCATION_TIMEOUT`) is returned". (https://vercel.com/docs/functions/configuring-functions/duration)
- Limits with Fluid **disabled**: UNCONFIRMED. The live limits page documents only "limits and restrictions of using Vercel Functions with Fluid compute"; the legacy pricing page gives no duration table. (https://vercel.com/docs/functions/limitations ; https://vercel.com/docs/functions/usage-and-pricing/legacy-pricing)
- App Router: `export const maxDuration = 5;` in `route.ts` ("the Next.js app router uses a named maxDuration export"). Next.js lists the option's default as "Set by deployment platform". (https://vercel.com/docs/functions/configuring-functions/duration ; https://nextjs.org/docs/app/api-reference/file-conventions/route-segment-config)
- `vercel.json`: `{"functions": {"app/api/**/*": {"maxDuration": 5}}}`. The value is "an integer number of seconds between `1` and your plan's maximum limit"; the string `max` "is also accepted and resolves to your plan's maximum at deploy time, but not to the extended max duration beta". With a `src` directory "you will need to prefix your function routes with `/src/`". (https://vercel.com/docs/project-configuration/vercel-json#functions ; https://vercel.com/docs/functions/configuring-functions/duration)
- Precedence: function code, then `vercel.json`, then dashboard, then Fluid defaults. (https://vercel.com/docs/fluid-compute#order-of-settings-precedence)
- Memory/CPU — Hobby: default and maximum "2 GB / 1 vCPU". Pro / Enterprise: default "2 GB / 1 vCPU", maximum "4 GB / 2 vCPU". "You cannot set your memory size using `vercel.json`"; "Hobby users cannot configure this size". (https://vercel.com/docs/functions/limitations#memory-size-limits ; https://vercel.com/docs/functions/configuring-functions/memory)
- Request body: "Vercel Functions accept request bodies up to **4.5 MB** by default". "Request bodies up to **20 MiB** are available in **Public Beta**", which needs Fluid, function memory "Performance (4 GB), available on Pro and Enterprise plans", and `VERCEL_SUPPORT_LARGE_REQUEST_BODY=1`. Over the limit: "413: `FUNCTION_PAYLOAD_TOO_LARGE`". (https://vercel.com/docs/functions/limitations#request-body-size)
- Response body: "The response body size limit is **4.5 MB**, except for streamed responses". (https://vercel.com/docs/functions/limitations#request-body-size)
- Other limits: uncompressed bundle "250 MB"; "1,024 file descriptors shared across all concurrent executions"; default region `iad1`; multi-region functions on Hobby: "No". (https://vercel.com/docs/functions/limitations ; https://vercel.com/docs/fluid-compute#default-settings-by-plan)
- Instances are shared: with Fluid, "multiple invocations can share the same physical instance (a global state/process) concurrently". Module-level state is therefore shared between concurrent requests and is not durable. (https://vercel.com/docs/fluid-compute#isolation-boundaries-and-global-state)
- Billing model: "Waiting for I/O (e.g. calling AI models, database queries) does not count towards active CPU time"; provisioned memory is billed while an instance is handling requests. (https://vercel.com/docs/functions/limitations#cost-and-usage)
- `getDeadline()` from `@vercel/functions` "Returns the shared invocation deadline for the current function invocation as a `Date` object" and `undefined` outside the Vercel runtime. (https://vercel.com/docs/functions/functions-api-reference/vercel-functions-package#getdeadline)
- After-response work: "If you’re using **Next.js 15.1 or above**, we recommend using the built-in `after()` function"; "Promises passed to `waitUntil()` will have the same timeout as the function itself". (https://vercel.com/docs/functions/functions-api-reference/vercel-functions-package)
- Client disconnects: "Cancellation is opt-in" (`"supportsCancellation": true` per path in `vercel.json`); when enabled "the signal fires and the function is terminated". (https://vercel.com/docs/functions/functions-api-reference#cancel-requests)
- Long quiet responses: "HTTP/1.1 clients and intermediate network layers may still close idle connections. For those cases, stream progress or heartbeat data while work is running." (https://vercel.com/docs/functions/configuring-functions/duration#extended-max-duration-beta)

## 2. Node.js runtime versions

- Available versions are listed as "**26.x** (default)", "**24.x**" and "**22.x**". "By default, a new project uses the latest Node.js LTS version available on Vercel." "Only major versions are available." (https://vercel.com/docs/functions/runtimes/node-js/node-js-versions)
- Selection: Project Settings → Build and Deployment → Node.js Version, and `engines.node` in `package.json` "to override the one you have selected in the Project Settings". A range such as `>=22.0.0` maps to "latest **26.x** version". (https://vercel.com/docs/functions/runtimes/node-js/node-js-versions)
- Node.js 26 went GA on Vercel on October 29, 2026: "Node.js 26 is the default for all new projects"; prebuilt deployments need "Vercel CLI version 65.8.0 or later". (https://vercel.com/changelog/node-js-26-lts-is-now-generally-available-on-vercel)
- Behaviour change on 26: "the built-in `fetch` negotiates HTTP/2 with servers that support it. For HTTP/2 responses, `response.statusText` is empty." Opt out with `VERCEL_FETCH_DISABLE_H2=1`. (https://vercel.com/docs/functions/runtimes/node-js/advanced-node-configuration)
- Next.js 16 requires "Node.js 20.9+ | Minimum version now `20.9.0` (LTS); Node.js 18 no longer supported". (https://nextjs.org/docs/app/guides/upgrading/version-16)

## 3. Durable execution: Workflows, Queues, Cron Jobs, Schedules

- Vercel Workflows is GA: "**Vercel Workflows is generally available on April 16.**" (post dated 2026-04-16). It uses the `workflow` npm package with `'use workflow'` and `'use step'`; a step "gives it built-in retries", and "Each step compiles into an isolated API route". (https://vercel.com/blog/a-new-programming-model-for-durable-execution ; https://vercel.com/docs/workflows/concepts)
- Workflows on Hobby: "Workflow Events | 50,000 events / month included | $0.02 per 1K events"; "Workflow Data Written | 1 GB | $0.50 per GB"; "Workflow Data Retained | — | $0.50 per GB-month" (not available on Hobby). Functions and Queue operations used by a run are billed separately. (https://vercel.com/docs/workflows/pricing)
- Workflow run limits: "Events per run | 25,000", "Steps per run | 10,000", "Max payload size | 50 MB", "Max workflow replay duration | 240s", "Maximum run duration | No limit"; a step's runtime follows Functions limits. Rate limit on Hobby: "50,000" requests per minute. (https://vercel.com/docs/workflows/pricing#workflow-run-limits)
- Step duration on Hobby: extended durations "are not available on Hobby plans, which remain limited to 5 minutes (300 seconds)". (https://vercel.com/changelog/workflow-steps-now-support-extended-function-durations)
- Vercel Queues is beta: "Vercel Queues are available in Beta on all plans" (public beta since 2026-02-27), with "at-least-once delivery". Consumers are declared with `experimentalTriggers: [{ "type": "queue/v2beta", "topic": ... }]`, and "Adding a trigger makes the route private". (https://vercel.com/docs/queues ; https://vercel.com/changelog/vercel-queues-now-in-public-beta)
- Queues pricing and limits: Hobby includes "First 1,000,000" API operations; Pro is "Starting at $0.60 per 1M"; "Messages are metered in 4 KiB chunks". Retention 60 seconds to 7 days (default 24 hours); visibility timeout up to 60 minutes; max message size 100 MB. (https://vercel.com/docs/queues/pricing ; https://vercel.com/pricing)
- Cron Jobs are legacy but still work on all plans: "Cron Jobs are a legacy feature and will be migrated to Schedules in the future." Limits: Hobby "100 cron jobs", minimum interval "Once per day", precision "Per-hour (±59 min)"; Pro and Enterprise "Once per minute". (https://vercel.com/docs/cron-jobs/usage-and-pricing)
- Hobby cron is enforced at deploy time: "Cron expressions that would run more frequently will fail during deployment." (https://vercel.com/docs/cron-jobs/usage-and-pricing)
- Cron mechanics: Vercel "makes an HTTP GET request to your project's production deployment URL"; "The timezone is always UTC"; user agent `vercel-cron/1.0`. A `CRON_SECRET` env var is "automatically sent as an `Authorization` header" with the `Bearer` prefix. (https://vercel.com/docs/cron-jobs ; https://vercel.com/docs/cron-jobs/manage-cron-jobs)
- Cron reliability: "Vercel will not retry an invocation if a cron job fails"; "Cron job delivery is best effort"; delivery "can also occasionally invoke the same scheduled run more than once". (https://vercel.com/docs/cron-jobs/manage-cron-jobs)
- Vercel Schedules is the successor and is beta: "Vercel Schedules is now in public beta on all plans" (2026-11-05). Pricing: "$5 per 1M runs and $10 per 1M creations on Pro and Enterprise. Hobby includes 500 schedule creations and 5,000 runs per month." (https://vercel.com/changelog/vercel-schedules-is-now-in-public-beta)
- Schedules on Hobby: most frequent cron schedule "Every 15 minutes"; jitter window "Always 15 minutes"; payload "16 KB". Past the monthly creation or run limit, Vercel blocks creating, enabling and manually running schedules, and "Scheduled runs, which Vercel skips", until the next billing period. (https://vercel.com/docs/schedules/limits)

## 4. PostgreSQL

- There is no first-party Postgres: "Vercel Postgres is no longer available. If you had an existing Vercel Postgres database, we automatically moved it to Neon in December 2024. For new projects, install a Postgres integration from the Marketplace". (https://vercel.com/docs/postgres)
- Providers: "For Postgres, you can use providers like Neon, Prisma Postgres, Supabase, or AWS Aurora Postgres." "Marketplace Storage Integrations are available on all plans". The Hobby plan's own storage row lists only "Blob". (https://vercel.com/docs/marketplace-storage ; https://vercel.com/docs/plans/hobby)
- Env injection: "The integration automatically injects credentials into your projects as environment variables". `vercel install neon` "provisions the resource, connects it to the currently linked project, and runs `vercel env pull` to sync credentials into `.env.local`"; without `--environment` it connects `production`, `preview` and `development`. (https://vercel.com/docs/marketplace-storage)
- "Existing deployments do not get new or changed variables. Create a new deployment after you connect a resource, change the environment scope, or rotate a secret." A custom prefix can be set per connection (e.g. `DB1_PGHOST`). (https://vercel.com/docs/marketplace-storage ; https://vercel.com/docs/integrations/install-an-integration/product-integration)
- Neon variable names (the listing's `.env.local` snippet): `DATABASE_URL` ("Recommended for most uses"), `DATABASE_URL_UNPOOLED` ("For uses requiring a connection without pgbouncer"), `PGHOST`, `PGHOST_UNPOOLED`, `PGUSER`, `PGDATABASE`, `PGPASSWORD`, plus "Parameters for Vercel Postgres Templates": `POSTGRES_URL`, `POSTGRES_URL_NON_POOLING`, `POSTGRES_USER`, `POSTGRES_HOST`, `POSTGRES_PASSWORD`, `POSTGRES_DATABASE`, `POSTGRES_URL_NO_SSL`, `POSTGRES_PRISMA_URL`. Neon regions offered: `cle1`, `iad1`, `pdx1`, `fra1`, `lhr1`, `syd1`, `sin1`, `gru1`. (https://vercel.com/marketplace/neon)
- Free tier: the Neon listing says "Plans starting at $0" and "Neon offers a generous **Free Plan**"; with a new Neon account "Billing is managed through Vercel". The docs' CLI example passes `--billing-plan free`. Marketplace storage means "Unified billing: Pay for storage resources through your Vercel account", and "Native integrations appear with a `billable` badge". (https://vercel.com/marketplace/neon ; https://vercel.com/docs/marketplace-storage ; https://vercel.com/docs/integrations/install-an-integration/product-integration)
- Free-plan quotas, and whether a `$0` plan can later incur charges or needs a payment method: UNCONFIRMED on vercel.com (provider-defined). The docs say only to run `vercel integration add <integration-name> --help` "to see integration-specific options like available metadata keys and billing plans". (https://vercel.com/docs/integrations/install-an-integration/product-integration)
- Driver guidance from Vercel: "we recommend using connection pooling with Fluid compute" — a `pg` `Pool` created in global scope plus `attachDatabasePool(pool)` from `@vercel/functions`, which "ensures that idle pool clients are properly released before functions suspend" and "Supports PostgreSQL (pg), MySQL2, MariaDB, MongoDB, Redis (ioredis), Cassandra (cassandra-driver), and other compatible pool types". (https://vercel.com/kb/guide/connection-pooling-with-functions ; https://vercel.com/docs/functions/functions-api-reference/vercel-functions-package#attachdatabasepool)
- Pool settings Vercel recommends: "Set a low idle timeout" ("e.g., 5 seconds"); "Avoid max pool size of 1: This does not reduce total connections and harms concurrency in Fluid Compute." (https://vercel.com/kb/guide/connection-pooling-with-functions)
- `@neondatabase/serverless` is not mentioned anywhere in the Vercel docs full text (https://vercel.com/docs/llms-full.txt); it appears only as a snippet on the Neon listing (`const sql = neon(process.env.DATABASE_URL)`). HTTP-versus-WebSocket transaction behaviour and interactive-transaction support: UNCONFIRMED. (https://vercel.com/marketplace/neon)
- Placement: "Deploy your databases in regions closest to your Functions." (https://vercel.com/docs/storage#best-practices)

## 5. Deployment Protection

- Defaults: "New projects start with Standard Protection and Vercel Authentication, unless your team has set a different default. ... Your production domains stay public." (https://vercel.com/docs/deployments/environments)
- Standard Protection (all plans) "protects all domains except production domains"; "Production domains include custom domains such as `example.com` and the `.vercel.app` domains assigned to production." (https://vercel.com/docs/deployment-protection#standard-protection ; https://vercel.com/docs/deployment-protection/methods-to-protect-deployments/password-protection)
- All Deployments (all plans) "Protects **all** URLs, including production domains"; "Vercel Authentication for All Deployments and Deployment Protection Exceptions do not require a paid add-on." (https://vercel.com/docs/deployment-protection)
- Plan matrix — Vercel Authentication: Hobby "Included". Password Protection: Hobby "Not available", Pro "$20 per month per protected project", Enterprise included. Trusted IPs: Enterprise only. Protection Bypass for Automation: "Included" on all plans. Shareable Links on Hobby: "Included, limited to one link per account". (https://vercel.com/docs/deployment-protection/usage-and-pricing)
- Vercel Authentication admits logged-in Vercel users with project access; "Those on the Hobby plan can only have one external user per account." (https://vercel.com/docs/deployment-protection/methods-to-protect-deployments/vercel-authentication)
- Bypass for automation: header or query parameter `x-vercel-protection-bypass` with the project secret, exposed to deployments as `VERCEL_AUTOMATION_BYPASS_SECRET`. It skips Password Protection, Vercel Authentication and Trusted IPs checks but cannot override "Active DDoS mitigations". (https://vercel.com/docs/deployment-protection/methods-to-bypass-deployment-protection/protection-bypass-automation)
- "Deployment Protection requires authentication for all requests, including those to Routing Middleware." WAF rules are evaluated after protection admits a request. (https://vercel.com/docs/deployment-protection)
- Preview deployments carry `X-Robots-Tag: noindex` unless served from a custom domain assigned to a branch. (https://vercel.com/docs/deployments/environments)

## 6. Environment variables

- Scopes: Production, Preview (optionally one Git branch), Development, and custom environments (Hobby: "Not available"; Pro: "1 environment"). (https://vercel.com/docs/environment-variables#environments ; https://vercel.com/pricing)
- "Any change you make to environment variables are not applied to previous deployments, they only apply to new deployments." (https://vercel.com/docs/environment-variables)
- "Sensitive" was renamed: each variable is **Config** or **Secret**. "Secret values are write-only after saving"; "Existing Sensitive environment variables continue to work as Secrets"; "Secrets are allowed in Development. This reverses the earlier rule that limited Sensitive environment variables to Production and Preview." (https://vercel.com/docs/environment-variables/sensitive-environment-variables)
- CLI: `vercel env add` takes `--type secret` (equivalent to `--sensitive`) or `--type config`. "You cannot convert a saved Secret to Config in place." (https://vercel.com/docs/environment-variables ; https://vercel.com/docs/environment-variables/sensitive-environment-variables)
- Build-log redaction: "if a Secret environment variable value is 32 characters or longer and appears in build logs, Vercel replaces the value with `[REDACTED]`". Shorter values are not covered by that sentence. (https://vercel.com/docs/environment-variables/sensitive-environment-variables#build-log-redaction)
- Size: "a total of **64 KB** in Environment Variables **per-Deployment**", and "no **single** variable can be larger than 64 KB". Count: "The maximum number of Environment Variables per environment per Project is `1000`." (https://vercel.com/docs/environment-variables#environment-variable-size ; https://vercel.com/docs/limits#environment-variables)
- Integration-created variables "can't be changed to Secret from the environment variables list"; the resource must be reconnected with Development deselected and **Sensitive** enabled. (https://vercel.com/docs/environment-variables/sensitive-environment-variables)
- Browser exposure in Next.js: "**By default, environment variables are only available on the server**. To expose an environment variable to the browser, it must be prefixed with `NEXT_PUBLIC_`." Values are inlined "into the JavaScript bundle during `next build`", and "dynamic lookups will *not* be inlined". (https://nextjs.org/docs/app/guides/environment-variables)
- "In Next.js, only environment variables prefixed with `NEXT_PUBLIC_` are included in the client bundle. If variables are not prefixed, Next.js replaces them with an empty string." (https://nextjs.org/docs/app/getting-started/server-and-client-components)

## 8. Security headers, CSP, and `proxy.ts`

- Static headers: "To set custom HTTP headers you can use the `headers` key in `next.config.js`" (sync or async function returning `{ source, headers: [{ key, value }] }`). "Headers are checked before the filesystem which includes pages and `/public` files." The page documents HSTS, `X-Frame-Options`, `Permissions-Policy`, `X-Content-Type-Options` and `Referrer-Policy`. (https://nextjs.org/docs/app/api-reference/config/next-config-js/headers)
- `headers()` and Proxy are both unsupported with `output: 'export'` (static export "Unsupported Features" lists "Headers", "Proxy", "Cookies" and "Route Handlers that rely on Request"). (https://nextjs.org/docs/app/guides/static-exports)
- CSP without nonces is the documented static option: "For applications that do not require nonces, you can set the CSP header directly in your `next.config.js` file"; the sample uses `script-src 'self' 'unsafe-inline'` and `style-src 'self' 'unsafe-inline'`. (https://nextjs.org/docs/app/guides/content-security-policy#without-nonces)
- Nonce CSP requires dynamic rendering: "you **must use dynamic rendering to add nonces**"; "When you use nonces in your CSP, **all pages must be dynamically rendered**"; "**Partial Prerendering (PPR) is incompatible** with nonce-based CSP". Nonces are generated in Proxy; pages opt in with `await connection()`. (https://nextjs.org/docs/app/guides/content-security-policy)
- Hash-based alternative: `experimental.sri.algorithm` — "Experimental: Feature may change or be removed"; Turbopack supports it since 16.2. (https://nextjs.org/docs/app/guides/content-security-policy#subresource-integrity-experimental ; https://nextjs.org/blog/next-16-2-turbopack)
- Development needs `'unsafe-eval'`: "`unsafe-eval` is not required for production." (https://nextjs.org/docs/app/guides/content-security-policy)
- Rename confirmed: "The `middleware` filename is deprecated, and has been renamed to `proxy`". "The `edge` runtime is **NOT** supported in `proxy`. The `proxy` runtime is `nodejs`, and it cannot be configured." The file is `proxy.ts` at the project root or in `src`, exporting `proxy` plus an optional `config.matcher`. (https://nextjs.org/docs/app/guides/upgrading/version-16 ; https://nextjs.org/docs/app/api-reference/file-conventions/proxy)
- Edge runtime is deprecated for routes: `runtime` accepts "`'nodejs'` (default)" and "`'edge'` (deprecated)"; Vercel adds "Starting in Next.js 16.3, setting `runtime` to `edge` is no longer supported." (https://nextjs.org/docs/app/api-reference/file-conventions/route-segment-config/runtime ; https://vercel.com/docs/functions/functions-api-reference)
- Platform HSTS: "The `.vercel.app` domain and all subdomains support HSTS by default and are preloaded in browser HSTS lists. Custom domains also use HSTS." (https://vercel.com/docs/cdn-security)

## 9. Next.js 16 specifics

- Bundler: "Starting with **Next.js 16**, Turbopack is stable and used by default with `next dev` and `next build`". A custom `webpack` config makes `next build` "**fail**"; `--webpack` opts out. (https://nextjs.org/docs/app/guides/upgrading/version-16#turbopack-by-default)
- Web Workers under Turbopack have no dedicated reference section. Official mentions: magic comments "work with dynamic `import()`, `require()`, `require.resolve()`, and `new Worker()` expressions"; `turbopackWorkerAssetPrefix` is a "Custom asset prefix for Web Worker URLs (entrypoint + module chunks)". (https://nextjs.org/docs/app/api-reference/turbopack)
- Worker bootstrap changed in 16.2: "Previously, Web Workers were bootstrapped through a `blob://` URL... With the updated Worker bootstrap code, the `origin` correctly points to your domain name, and relative fetches succeed." (https://nextjs.org/blog/next-16-2-turbopack)
- The exact pattern `new Worker(new URL('./worker.ts', import.meta.url), { type: 'module' })` on Turbopack, and its CSP `worker-src` needs: UNCONFIRMED. The only verbatim support statement is for webpack 5: "Support for web workers using `new Worker(new URL("worker.js", import.meta.url))`". (https://nextjs.org/docs/messages/webpack5)
- Async request APIs: "Starting with **Next.js 16**, synchronous access is fully removed." Applies to `cookies`, `headers`, `draftMode`, `params` (including `route.js`) and `searchParams`. (https://nextjs.org/docs/app/guides/upgrading/version-16#async-request-apis-breaking-change)
- Linting: "The `next lint` command has been removed. Use Biome or ESLint directly. `next build` no longer runs linting." The `eslint` key in the Next config is also removed. (https://nextjs.org/docs/app/guides/upgrading/version-16#next-lint-command)
- Minimums: Node.js "`20.9.0`", TypeScript "`5.1.0`", browsers "Chrome 111+, Edge 111+, Firefox 111+, Safari 16.4+". (https://nextjs.org/docs/app/guides/upgrading/version-16#nodejs-runtime-and-browser-support)
- Route handler caching, previous model: "Route Handlers are not cached by default. You can, however, opt into caching for `GET` methods." (changed in `v15.0.0-RC`: "The default caching for `GET` handlers was changed from static to dynamic"). (https://nextjs.org/docs/app/getting-started/route-handlers#caching ; https://nextjs.org/docs/app/api-reference/file-conventions/route)
- Route handler caching with Cache Components: "`GET` handlers follow the same model as pages: they prerender when they don't access uncached or runtime data". Prerendering stops on request data, `cookies()`, `headers()`, `connection()`, database queries or non-deterministic operations. (https://nextjs.org/docs/app/guides/migrating-to-cache-components#route-handlers-get ; https://nextjs.org/docs/app/getting-started/route-handlers#with-cache-components)
- Cache Components is opt-in config but on in new apps: "New App Router apps created with the recommended `create-next-app` defaults already have Cache Components and Partial Prefetching enabled." Enable with `cacheComponents: true` and `partialPrefetching: true`. (https://nextjs.org/docs/app/getting-started/caching)
- With Cache Components, segment configs change: "`dynamic`, `dynamicParams`, `revalidate`, and `fetchCache` removed", and "Remove any `runtime` export, including `runtime = 'nodejs'`". (https://nextjs.org/docs/app/api-reference/file-conventions/route-segment-config ; https://nextjs.org/docs/app/api-reference/config/next-config-js/cacheComponents)
- With Cache Components, clock and randomness break prerender: "Calls like `new Date()`, `Date.now()`, `Math.random()`, and `crypto.randomUUID()` during prerender throw a build error"; fix by calling `connection()` first or moving the call "into a Client Component". (https://nextjs.org/docs/app/guides/migrating-to-cache-components)
- `server-only`: "if you try to import the module into a Client Component, there will be a build-time error." "In Next.js, installing `server-only` or `client-only` is **optional**." (https://nextjs.org/docs/app/getting-started/server-and-client-components)
- Bundled docs: "Next.js 16.2 and later include documentation that matches the installed framework version. The documentation is available at `node_modules/next/dist/docs/`". (https://nextjs.org/docs/app/guides/ai-agents)
- Side effect to expect: when `next dev` detects a coding agent it "creates or updates" a managed block in `AGENTS.md`; this is "enabled by default" from 16.3 and disabled with `agentRules: false`. (https://nextjs.org/docs/app/api-reference/config/next-config-js/agentRules)

## 11. Deployment flow, CLI, MCP, rollback

- Git: "Vercel allows for **automatic deployments on every branch push**". "A Production deployment will be created each time you merge to the **production branch**" (chosen as `main`, else `master`); every other branch gets preview deployments. (https://vercel.com/docs/git)
- Hobby Git limits: "Vercel does not support connecting a project on your Hobby team to Git repositories owned by Git organizations." For private repositories, "To deploy commits under a Hobby team, the commit author must be the owner of the Hobby team"; the docs add that this "does not apply to collaborators on personal Git accounts". (https://vercel.com/docs/limits ; https://vercel.com/docs/git#deploying-private-git-repositories)
- CLI from a directory, no Git: `vercel` creates a preview and `vercel --prod` a production deployment. "The first deployment of a new project is always a production deployment, even when you omit `--prod`." (https://vercel.com/docs/cli/deploy ; https://vercel.com/docs/environment-variables#environments)
- Prebuilt: `vercel pull`, `vercel build` (output in `.vercel/output`), then `vercel deploy --prebuilt`, which creates a deployment "*without* sharing the Vercel Project's source code with Vercel". Caveat: "System Environment Variables will be missing at build time". (https://vercel.com/docs/cli/build ; https://vercel.com/docs/cli/deploy#prebuilt)
- CLI upload limits: "`15,000`" source files unless `--archive=tgz`; source size "100 MB for Hobby". (https://vercel.com/docs/limits#files)
- Without an account: `vercel deploy --temporary`; "Temporary deployments expire unless claimed to a free Hobby account." (https://vercel.com/pricing ; https://vercel.com/docs/cli/deploy#temporary)
- Vercel MCP: "a remote MCP with OAuth" at `https://mcp.vercel.com`. `create_git_project` "By default ... creates a preview deployment from the repository's production branch". `deploy_to_vercel` takes inline files with "Limits: 300 files, 3 MiB per file, 4 MiB total encoded contents" and is not registered on project-scoped connections. (https://vercel.com/docs/agent-resources/vercel-mcp ; https://vercel.com/docs/agent-resources/vercel-mcp/tools/projects/create_git_project ; https://vercel.com/docs/agent-resources/vercel-mcp/tools/deployments/deploy_to_vercel)
- Instant Rollback on Hobby: "Hobby users can roll back to the immediately previous deployment." The CLI refuses older targets: "To rollback further than the previous production deployment, upgrade to pro." (https://vercel.com/docs/instant-rollback ; https://vercel.com/docs/cli/rollback)
- Rollback side effects: "After a rollback, Vercel turns off auto-assignment of production domains" until a deployment is promoted (`vercel promote`). "Vercel won't update environment variables if you change them in the project settings and will roll back to a previous build". (https://vercel.com/docs/instant-rollback)
- Retention: Hobby and Pro default to "30 days" for every deployment state; Hobby always keeps the "Last 3" production deployments in state Ready. (https://vercel.com/docs/deployment-retention)

## 12. A hosted PostgreSQL behind a pooler (the provider's own documentation, read 2026-11-25)

Section 4 left this open because the research was limited to vercel.com and nextjs.org. These are from Neon's
documentation, the provider whose Marketplace listing section 4 quotes. Page dates are the pages' own "Last
updated".

- Pool mode: "Neon uses PgBouncer in transaction mode (`pool_mode=transaction`)", with `max_client_conn=10000`,
  `default_pool_size=0.9 * max_connections`, `max_prepared_statements=1000`, `query_wait_timeout=120`; "These
  settings are not user-configurable." (https://neon.com/docs/connect/connection-pooling, 2026-11-14)
- Startup parameters: "PgBouncer allows only startup parameters it can keep track of in startup packets."
  "These include: `client_encoding`, `datestyle`, `timezone`, `standard_conforming_strings`, and
  `application_name`." The error texts are "unsupported startup parameter: <...>" and "unsupported startup
  parameter in options: <...>", and the advice is "Please use unpooled connection or remove this parameter from
  the startup package." (https://neon.com/docs/connect/connection-errors, 2026-11-20)
- Not supported with pooled connections: "SET / RESET (session variables)", "LISTEN / NOTIFY", "WITH HOLD
  CURSOR", "PREPARE / DEALLOCATE (SQL-level prepared statements)", "Temporary tables with PRESERVE / DELETE
  ROWS", "LOAD statement", "Session-level advisory locks". Supported: "PgBouncer supports protocol-level
  prepared statements (as of PgBouncer 1.22.0)". For a schema the page's fix is `SET LOCAL` or `ALTER ROLE`.
  (https://neon.com/docs/connect/connection-pooling)
- "PgBouncer doesn't reset a server connection when it returns to the pool in transaction mode."
  (https://neon.com/docs/connect/connection-pooling)
- Pooled and direct strings differ by the host: "Add `-pooler` to your endpoint ID".
  (https://neon.com/docs/connect/connection-pooling)
- Connections: the smallest compute (0.25 CU, 1 GB) has `max_connections` 112, of which "Seven connections are
  reserved for the Neon superuser account"; the pooler accepts "up to 10,000 concurrent connections".
  (https://neon.com/docs/connect/connection-pooling)
- What the Vercel-managed integration sets: "`DATABASE_URL` | Pooled connection string (PgBouncer)",
  "`DATABASE_URL_UNPOOLED` | Direct connection string", "`PGHOST`, `PGHOST_UNPOOLED`, `PGUSER`, `PGDATABASE`,
  `PGPASSWORD` | Raw pieces to build custom strings", "`POSTGRES_*` (legacy)". A "Custom Prefix" changes the
  names. (https://neon.com/docs/guides/vercel-managed-integration, 2026-11-18)
- Free plan: "$0/month"; "100 CU-hours/project"; storage "1 GB/project, 20 GB account total"; scale to zero
  "After 5 min" ("Free: 5 min inactivity; cannot disable"); "On the Free plan, when you run out of CU-hours,
  your compute is suspended until the next billing period or until you upgrade." "On the **Free** plan, there
  is no monthly cost." Whether a payment method is needed: not stated. (https://neon.com/docs/introduction/plans,
  2026-11-24)
- Waking: "The transition from an idle to an active state only takes a few hundred milliseconds."
  (https://neon.com/docs/connect/connection-errors)
- History on the Free plan: "6 hours, up to 1 GB of changes"; "1 manual snapshot"; "scheduled backups are not
  available on the Free plan". (https://neon.com/docs/introduction/plans)
