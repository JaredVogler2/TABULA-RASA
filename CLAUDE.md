# CLAUDE.md — standing engineering contract

Read prompts/00-MASTER.md and prompts/README.md before implementation or resumption. This is a product and research program, not a frozen specification. Owner intent: maximize the capabilities of Fable 5.2, build a premium Vercel browser game, enable owner-controlled Claude API cognition, and investigate emergent institutions without scripting outcomes.

## Non-negotiable
- World simulation is authoritative; model actions are proposals, validated and applied by engine. No hidden civilization blueprint or scripted outcomes in blank-slate mode.
- Real game loop, excellent visual design, desktop and mobile. No placeholder-only release.
- Default no spend; $200 stated envelope, explicit authorization for any paid pilot/study, durable fail-closed budget and owner-only API. No secrets in client/repo/logs; no agent access to external tools.
- No false claims about tests, deployments, emergence, science, model availability, cost or human/device testing.
- Keep offline deterministic baseline and no-cost recorded replay.
- Preserve existing work and clean commits; do not force-push, overwrite unrelated code, or create paid infrastructure without approval.

## Fable's design authority
You are encouraged to improve algorithms, architecture, art, UX, research methodology and phase ordering. Record material changes in docs/DECISIONS.md with ID, date, problem, original proposal, alternatives, evidence, decision, affected acceptance tests, cost/risks and rollback. Update impacted docs and tests; benchmark or prototype first when practical. You may strengthen gates and add phases. Do not silently weaken scope or bypass hard constraints. Only ask the owner for irreversible/cost/security decisions or conflicts with core intent; proceed on reversible design choices. Do not use this autonomy to reinterpret authorization to spend.
 
## Execution
Maintain docs/PROGRESS.md and docs/CONTINUE_HERE.md (phase, exact commit, commands, results, blockers, next action) and docs/EVIDENCE.md. Each phase ends with executed checks, screenshots/benchmarks when relevant and a scoped commit. A phase is PASS only if its gates are actually proven; otherwise PARTIAL/BLOCKED/NOT RUN. Keep a usable vertical slice. Follow version-matched official docs rather than guessed APIs. No fabricated citations. Read previous decisions before modifying contracts.
